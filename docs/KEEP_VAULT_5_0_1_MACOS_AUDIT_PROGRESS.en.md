## Work sequence and completion criteria

1. Review the current macOS state, preserve existing changes, and independently verify the installed artifacts.
2. Assess chunk parallelism with one slot per four logical CPUs as the starting point. Account for memory, nested parallelism, small inputs, cancellation, scheduling failures, and canonical output.
3. Perform repeated performance measurements and independent cryptographic comparison tests. Explicitly identify hardware limits and unmeasured platforms.
4. Perform code and security analysis, regression tests, a native build, and the complete parallel macOS test set. The project instruction dated 05.09.2026 replaces the additional serial full test with the parallel full test. Internal serial reference comparisons and isolated performance measurements remain.
5. Install the signed build and run real GUI tests using exclusively synthetic data, including Paranoia and a complex directory structure. Retain comparison originals; perform the additionally requested deletion test exclusively on a separate disposable copy.
6. Run the final mandatory complex Paranoia end-to-end gate. Afterward, perform only non-mutating artifact and Git checks.
7. Commit and push only reviewed changes. Create GitHub release `v5.0.1` only as a draft. Public release additionally requires Developer ID, notarization, stapling, and Gatekeeper success.

## Limits

A finite audit can prove neither the absence of all vulnerabilities nor optimal performance on arbitrary hardware. The result identifies verified properties, discovered defects, actual measurements, and remaining blockers.
