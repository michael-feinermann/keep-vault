# Keep Vault 5.0.2: additional local password model

[Deutsch](README.de.md) · [English](README.en.md) · [Documentation index](../README.en.md)

Complete documentation translation of the [embedded model text](../../KalynaArchiver/Resources/PasswordModel/README.md). Relative filenames below refer to that resource directory. The signed resources remain unchanged; language editions are maintained only here.

Model version: `keep-vault-password-model-2026-09-06-v1`, data retrieved on 6 September 2026. These files are analysis data for archive creation only. Keep Vault does not generate user passwords, PINs or wallets from them. At runtime there are no network requests, downloads, telemetry, HIBP lookups or online activation. An older bundled data version also remains fully usable offline.

`manifest.json` binds sources, fixed Git revisions, SHA256 values of original and output files, entry counts, transformations and licenses. Its SHA256 is also embedded in the source of `PasswordModelData`. The loader first checks the manifest, then every required data and license file. The resources are embedded in the application and therefore form part of the signed application candidate. Checksums detect deviations from the expected state; they do not replace the outer code signature or its trust verification.

## Contract and limits of the claims

All existing password rules and the original calculation remain: 24 to 256 UTF-16 code units, at least three character classes, twelve distinct characters, twelve non-hex characters, at most seven consecutive hex characters, no control characters or invalid UTF-16 sequences, existing factor comparisons and at least 128.0 conservative model bits. The new assessment is exclusively `min(Halt, HvollständigesModell1, …)`. Missing model coverage cancels neither a recognized weakness nor an existing rejection. An exact match in the bounded list of complete blocked passwords is an additional rejection.

The number estimates guessing effort or provides a limiting model value. It is neither Shannon entropy nor min-entropy, measured attack time, nor proof that at least `2^128` attempts are necessary. The additional rank/grammar models have not been empirically calibrated. Products of ranks are not reported as the exact rank of a merged, deduplicated attack list. In particular, `1/P` of a word probability is not interpreted as an exact guess rank. The existing 128-bit product threshold nevertheless remains mandatory and unchanged. The zxcvbn reference itself primarily addresses low guessing budgets; this does not calibrate this model for an offline vault.

Only explicit wordlist spaces have an exactly calculable combinatorial upper bound: `k * log2(W)` for a fixed representation. Uniform, independent selection by the user is not assumed. Frequency, repetition and language models may further limit the same complete value. A word match alone is not a rejection.

For empty input, impermissible length, control characters or invalid UTF-16, the lazy data remains unloaded. Missing, damaged or inconsistent data produces `ModelUnavailable` and prevents a positive archive-creation decision. Extraction, listing, recovery and key derivation must not invoke this model and do not depend on its availability. An internal asynchronously isolated test scope throws on every Evaluate or direct loader call, including with a populated cache; it cannot allow acceptance.

Analysis variants change local copies only. Password, spaces and PIN continue to enter the v12 KDF unchanged through the existing UTF-8/ASCII path. The result object contains no input, matched words, normalized text or keys. Temporary .NET analysis strings are managed immutable strings; guaranteed erasure of these additional GC copies is not claimed. Inputs are neither logged nor persistently stored.

## Complete model families

Segmentation forms a directed acyclic graph over valid Unicode scalar boundaries. Every path spans the first through the last input character. Overlapping word/name/list matches, ambiguous concatenations and other complete paths compete through their minimum. Selection of a word sequence and its order is captured by the ordered token derivation. A local word value never limits a password while ignoring the rest.

The general grammar charges three selection bits per token for eight families: lexicon, morphology, sequence/suffix, keyboard, year/date, repetition, unknown remainder and separator. Ranked tokens use `log2(Rang)`; lists and names use `log2(verifizierte Listengröße)`. This is a declared combination of estimated attack costs, not an empirically calibrated joint distribution. Entire known phrases form their own bounded lexicon enumeration. The synthetic Sommer/Wiese example from the requirements is explicitly not a data entry and remains an independent regression test.

- Fixed representations: For exactly matching complete paths, a uniform separator chosen from space, hyphen, underscore or period, and uniform initial capitals or all-capitals, are each charged once with two selection bits. The path explicitly consumes the separators. Unknown parts remain in their original form and continue to pay their complete remainder-description cost. Separate representation variants per token remain possible as an alternative. Mixed case counts the choices for individual letters.
- Wordlists: Complete list words, separated or concatenated without separators, additionally receive the exact `k*log2(W)` cap for a fixed representation. Multiple possible segmentations and list overlaps are handled by taking the minimum. Typical capitalization receives separate complete transformation costs. Spaces are not treated as additional random characters.
- BIP39: Only the five word counts 12/15/18/21/24 and original 11-bit indices are used. SHA256 checks the 4/5/6/7/8 checksum bits. The additional 128/160/192/224/256-bit list space applies only for a valid checksum. Invalid checksums do not remove the normal wordlist cap. Temporary packed entropy and hash bytes are cleared. There is no wallet-seed or BIP39-PBKDF2 derivation. Known public examples and repetition may impose stronger limits.
- BIP39 variations: The same original indices are also checked for fixed hyphen/underscore/period separation, concatenation and the declared leet recognition. Uniform capitalization is described jointly with at most two selection bits; other fixed representations receive three selection bits. The complete segmentation graph contains valid checksum groups as components, so prefixes, years, appended characters and unknown remainders retain their own complete costs. A complete password with an added prefix or suffix is not reported as a fully valid mnemonic. The component search processes at most 4,096 states per start position; unrecognized derivations are neutral. Temporary index arrays are explicitly cleared after use or when the bounded search stops.
- Leet: Explicit ambiguous alternatives are `0/o`, `1/i/l`, `3/e`, `4/a`, `@/a`, `$/s`, `5/s`, `7/t`, `+/t`, `8/b` and `9/g`. Recognized substitutions pay for selection among their alternatives. At most 128 active trie paths are followed per step; discarded paths remain neutral and justify no additional strength.
- Unicode: The original representation and an explicitly described NFC/NFD transformation space are treated separately. Each canonically decomposable grapheme offers a choice between complete NFC and complete NFD; an additional choice identifies this family. Other orders of combining characters are analyzed in the original. German `ä/ae`, `ö/oe`, `ü/ue`, `ß/ss` variants are separate analysis paths. Arbitrary visually similar alphabets are not equated. Surrogate pairs count as one scalar in remainder analysis, not two independent characters.
- Periodic format characters: The explicit eight scalars U+200B, U+200C, U+200D, U+2060, U+FEFF, U+00AD, U+2063 and U+2062 can be analyzed as a fully reconstructable insertion family. All occurring alphabet members are examined independently of their order; the minimum of all applicable complete strategies applies. A selected character is removed only when all its positions follow exactly one of three rules: after each complete group without a trailing character, after each complete group with a possible trailing character, or before each group. Positive group length `p` is enumerated in ascending order; `log2(8*3*p)` describes character selection, placement mode and period rank. A single insertion alternatively costs `log2(8*(n+1))`, including its arbitrary position. Characters outside the selected family remain fully in the base value and retain their description costs. The base value itself needs a complete model path. Each competing strategy permits exactly one such transformation, without recursive combination of several format families. An additional prepended character may shift the period start outside the three defined modes; arbitrary start offsets are not modeled. Even a still-matching period does not guarantee a value below 128 when remaining characters carry costs. There is no blanket free Cf removal and no change to KDF input.
- Morphology: A bounded set of 21 suffixes and seven prefixes covers inflection, plurals and derivation. Four stem variants include the unchanged stem, an appended English `e`, removal of a doubled final letter and German umlaut stems. The joint selection costs `log2(28*4)`. Compounds arise from complete segmentations; this finite model is not a complete morphological parser.
- Years/date: Fixed reference year 2026 and year range 1900 to 2056. Six- and eight-digit calendar values and regular period/hyphen/slash formats are actually checked for valid days. Two-digit years are explicitly checked as 1900+YY and 2000+YY, without an OS- or culture-dependent cutoff year. Order, format and separators are included in the model space. This password analysis does not replace the separate mandatory PIN rejection for the actual current local date.
- Keyboard: QWERTY-US and QWERTZ-DE are separate physical grids with their shifted characters, including the digit row and punctuation. The eight adjacent directions, starting key, length, number and positions of direction changes and shift choices are described jointly. A globally fully shifted path receives one joint shift choice; mixed shift encodes positions. The grid is a documented attack model, not pixel-exact keyboard geometry. AltGr/dead-key composition is not fully modeled.
- Repetitions: A complete base block is described once using its own complete model or scalar space; base-block length and repetition count each receive eight selection bits. Equivalent nonprimitive periods are omitted. There is only one bounded level of base-block analysis. A remaining different suffix stays a further complete path component.
- Unknown remainder: Each contiguous remainder description counts its length and every Unicode scalar it contains. ASCII uses the formal 95-character space; other scalars use the formal Unicode scalar space excluding surrogates. This is a complete search-space upper bound, not an assumed random source. An unknown region receives no blanket strength bonus and may not disappear. The overall value can never increase the unchanged existing value; missing coverage is not a security endorsement.

The public API reports model status/version, the complete limiting value, model family, structural reasons, number of unknown scalars and, where applicable, BIP39 checksum status. It contains no password fragments. Displayed integers must not be rounded upward across the acceptance threshold.

## Bounded blocklist

The bundled version is neither an HIBP snapshot nor a complete breach collection. It contains 30,000 public aggregated zxcvbn candidates and six public examples. No match means only “no match in the bundled data.” Nothing can be concluded about later breaches or unknown compromised values. Neither HIBP frequency thresholds of 10/20 nor experimental PIN-bit thresholds are introduced as empirically established product limits.

The primary comparison matches the complete unchanged input using `Ordinal`. The selected source corpus already consists of lowercase candidates. Capitalization, leet, additions and word fragments belong in complete pattern analysis; they are not labeled as an additional proven leak. A dictionary word within a long password is never a blocklist match for the whole value.

## Reproduction and checks

`import-model.py` is an explicitly manual maintenance tool. Neither the application nor the build script starts it. It downloads only the public source data and licenses identified above, checks the fixed list sizes, writes deterministic data and the manifest, and prints their hashes. It contains no user secrets. Run from the repository root: `python3 KalynaArchiver/Resources/PasswordModel/import-model.py`. A deliberate data change requires joint review of the model version, embedded manifest hash, attribution, regressions and signed candidate. The runtime never performs such a repair or update step.

`KeepVaultMac.Tests/PasswordModelTests.cs` checks the three list spaces, original indices, 24 published Trezor checksum vectors plus independently Python-derived 15-/21-word vectors, a checksum-bit-only mutation of each, list overlaps, representations, unknown remainders, leet, Unicode, morphology, physical shift paths, real calendar values, all selected existing rejection rules, the 128 threshold and `Hneu <= Halt`. Checksum components with appended material are additionally checked directly against their checksum-bit-only mutation, so accidentally cheaper rank paths cannot hide a missing checksum path. The Sommer/Wiese examples, their simple case/leet/year variants and fully periodic U+200B insertion between each pair of characters must remain below 128 in actual archive-creation assessment. Missing, mutated and oversized resources and asynchronously isolated Evaluate/Load prohibitions have dedicated tests. Runtime regression includes supported inputs up to 256 UTF-16 code units with long repetitions, varying periods, remainder changes, leet ambiguity and synthetic irregular values. Actual platform, GUI, offline, KDF-compatibility and release results are recorded separately in the audit; this text does not claim in advance that they passed.
