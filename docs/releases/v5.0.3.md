## Deutsch

# Keep Vault 5.0.3 für macOS: Releaseentwurf

Stand: 28.09.2026. Dieser Text beschreibt den aktuellen Quell- und Prüfstand gemäß REV9. Er ist keine Veröffentlichungsfreigabe. Ziel sind Produktversion 5.0.3, Build 14 und Containerformat v13. Der finale Paketsatz, die abschließende Signierungs-/Notarisierungsprüfung und der Installationsnachweis stehen noch aus. Bis zu deren dokumentiertem Abschluss bleibt v5.0.2 die veröffentlichte Referenz. Windows ist nicht Bestandteil dieses Durchgangs.

### Absichtlicher Formatbruch

5.0.3 erstellt und öffnet ausschließlich verschlüsselte Container im Format v13. Vorhandene v12-Container werden abgelehnt; es gibt kein Probeentschlüsseln, keinen automatischen Fallback und keine automatische Migration. Für alte Archive wird weiterhin eine dazu passende frühere Version benötigt. Benutzerarchive, KPAR2-Dateien, Schlüsselblätter und bisherige private Schlüssel werden durch diesen Versionswechsel nicht in das neue Format umgeschrieben.

### Änderungen

- Zwölf Suiten, einschließlich neuer Einzel-Suiten für Camellia-256-CTR und Serpent-256-CTR. Der Standard verwendet vier Stufen in Verschlüsselungsreihenfolge: AES, Kalyna, Threefish, XChaCha20-Poly1305. Paranoia verwendet acht: AES, MARS, Camellia, Serpent, SHACAL-2, Kalyna, Threefish, XChaCha20-Poly1305. Beide vollständigen globalen MACs bleiben zusätzlich verpflichtend. Paranoia behält zwei vollständige Master-KDF-Runden; die Argon2-Kosten werden nicht zugunsten der Geschwindigkeit reduziert.
- Alle Suiten speichern eine 320-Byte-Noncebasis, Paranoia zusätzlich eine zweite. Die Ableitung `Seed320-Blockwise64-SHA3-512-ActivePrefix-v3` bindet Suite, Stufenbedarf und 64-Bit-Chunkindex. Sie verarbeitet nur benötigte aktive Blöcke; die vollständige Basis einschließlich Reserve bleibt authentifiziert.
- Elf Entropiepools speichern unveränderte Mausrecords im gesperrten RAM. Die Zuordnung erfolgt mit unverzerrten OS-Zufallsziehungen. Generieren trennt den verbrauchten Bestand atomar ab. Pro Pool folgen Fisher-Yates und SHA3-Replay; Paranoia ergänzt einen unabhängigen zweiten Shuffle und SHA512-Replay. Alte Record-, Index- und Zwischenpuffer werden vor der Ergebnisfreigabe bereinigt. Reset, Abbruch und Cleanupfehler sind ausdrücklich behandelt. Diese Verarbeitung ist keine Entropiegarantie für menschliche Mausbewegungen.
- Verschlüsselte Eingaben verwenden einen privaten Ciphertext-Spool und einen diskgestützten Doppel-MAC-Index. Jeder gelesene Bereich wird erneut geprüft; normale Verbraucher erhalten erst nach beiden globalen MACs Zugriff. Reguläre ZPAQ-Eingaben lesen die gebundene Originaldatei über begrenzte authentifizierte Bereichsantworten. KPAR2-v4-Metadaten werden inkrementell und diskgestützt verarbeitet. Ein reparierter verschlüsselter Kandidat muss vor erfolgreichem Abschluss erneut vollständig authentifiziert werden.
- Einstellbare Ressourcenbudgets begrenzen Datenmengen, Arbeitsvolume, Metadaten, RAM, Entropiespeicher, CPU-Worker, I/O, Warteschlangen und Laufzeit. Verschachtelte Vorgänge teilen Reservierungen; gleichzeitig lebende native Modelle und KDF-Matrizen werden gemeinsam berücksichtigt. Neue freigegebene CPU-Zahlen erfordern keine pauschale 64-Worker-Grenze.
- Ein neuer externer Release-Schlüsselsatz für RSA-4096 und ML-DSA-87 ist als öffentlicher Vertrauensanker eingebunden. Private Schlüssel bleiben außerhalb des Repositorys im geschützten VeraCrypt-Speicher. Die getrennten Schlüsselhüllen behalten ihr bestehendes Format. Apple-Signatur, doppelte hybride Signaturen und die endgültigen Paketprüfungen bleiben erforderlich.

### Nachweise und offene Freigabe

Es liegen gezielte Kern-, Entropie-, Header-, Nonce-, Ressourcen- und native Referenzprüfungen vor. Die kleinen nativen Plain-/Read-at-/Pipe-Strukturrunden bestanden auf ARM64, x86_64 über Rosetta und ARM64 mit ASan/UBSan. Reale Archivtests sind auf Benutzerwunsch grundsätzlich auf 256 MiB begrenzt. Die zusätzlich genehmigte Paranoia-Strukturrunde umfasst 256 MiB variierte Dateien und Verzeichnisse plus eine einzelne 256-MiB-Datei. Die Genehmigung dieser Runde ist noch kein bestandener Lauf. Logische TiB-Grenztests belegen keine physisch verarbeiteten TiB-Daten und keine Windows-Freigabe.

Die aktuellen Einzelresultate, Wiederholungsläufe und noch offenen Gates stehen im [Testbericht](../KEEP_VAULT_5_0_3_TEST_REPORT.md), im [IO-Bericht](../KEEP_VAULT_5_0_3_MULTITB_TEST_REPORT.md) und im [Releasebericht](../KEEP_VAULT_5_0_3_RELEASE_REPORT.md). Endgültige Artefaktnamen, Hashes, Downloadvergleich und Installationsresultate werden erst nach tatsächlicher Prüfung ergänzt. Dieser Entwurf enthält keine behauptete Notarisierung oder abgeschlossene Veröffentlichung.

## English

# Keep Vault 5.0.3 for macOS: release draft

Status: 28 September 2026. This text describes the current source and test state under REV9. It is not release approval. The target is product version 5.0.3, build 14 and container format v13. The final package set, final signing/notarization checks and installation evidence remain pending. Until their completion is documented, v5.0.2 remains the published reference. Windows is outside the scope of this run.

### Intentional format break

5.0.3 creates and opens encrypted containers exclusively in format v13. Existing v12 containers are rejected; there is no trial decryption, automatic fallback or automatic migration. Old archives continue to require a compatible earlier version. This version transition does not rewrite user archives, KPAR2 files, key sheets or existing private keys into the new format.

### Changes

- Twelve suites, including new standalone Camellia-256-CTR and Serpent-256-CTR suites. The default has four stages in encryption order: AES, Kalyna, Threefish, XChaCha20-Poly1305. Paranoia has eight: AES, MARS, Camellia, Serpent, SHACAL-2, Kalyna, Threefish, XChaCha20-Poly1305. Both complete global MACs remain mandatory in addition. Paranoia retains two complete master-KDF rounds; Argon2 costs are not reduced for performance.
- Every suite stores a 320-byte nonce base, with a second base for Paranoia. `Seed320-Blockwise64-SHA3-512-ActivePrefix-v3` binds the suite, stage requirements and 64-bit chunk index. It processes only required active blocks; the complete base including its reserve remains authenticated.
- Eleven entropy pools retain unchanged mouse records in locked RAM. Routing uses unbiased OS-random selections. Generation atomically detaches the consumed record set. Each pool undergoes Fisher-Yates followed by SHA3 replay; Paranoia adds an independent second shuffle and SHA512 replay. Old record, index and intermediate buffers are cleaned before results are released. Reset, cancellation and cleanup failures are handled explicitly. This processing does not guarantee the entropy of human mouse movement.
- Encrypted input uses a private ciphertext spool and a disk-backed dual-MAC index. Every consumed range is rechecked; ordinary consumers receive access only after both global MACs pass. Regular ZPAQ input reads the bound original file through bounded, authenticated range responses. KPAR2-v4 metadata is processed incrementally using disk-backed storage. A repaired encrypted candidate must pass complete authentication again before successful completion.
- Configurable resource budgets bound data sizes, working volume, metadata, RAM, entropy storage, CPU workers, I/O, queues and execution time. Nested operations share reservations; concurrent native models and KDF matrices are accounted for together. Newly permitted CPU counts are not subject to a blanket 64-worker ceiling.
- A new external RSA-4096 and ML-DSA-87 release key set is incorporated through public trust anchors. Private keys remain outside the repository in protected VeraCrypt storage. The separate key envelopes retain their existing format. Apple signing, both hybrid signatures and final package checks remain required.

### Evidence and pending approval

Targeted core, entropy, header, nonce, resource and native reference checks have been performed. Small native plain/read-at/pipe structural roundtrips passed on ARM64, x86_64 through Rosetta and ARM64 with ASan/UBSan. At the user's request, real archive tests are generally limited to 256 MiB. The additionally authorized Paranoia structural roundtrip contains 256 MiB of varied files and directories plus one 256-MiB file. Authorization of that roundtrip is not a passing result. Logical TiB boundary tests do not establish physically processed TiB data or a Windows release.

Current individual results, reruns and pending gates are recorded in the [test report](../KEEP_VAULT_5_0_3_TEST_REPORT.md), [IO report](../KEEP_VAULT_5_0_3_MULTITB_TEST_REPORT.md) and [release report](../KEEP_VAULT_5_0_3_RELEASE_REPORT.md), currently available in German. Final artifact names, hashes, download comparisons and installation results will be added only after verification. This draft makes no claim of notarization or completed publication.
