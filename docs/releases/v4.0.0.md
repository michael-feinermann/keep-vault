## Deutsch

Containerformat **v9**, unverändert gegenüber 3.0.0. Mit 3.0.0 erstellte Archive lassen sich weiterhin öffnen. Geändert hat sich ihr Schutz, und das
Bundle meldet jetzt seine eigene Version korrekt: Frühere Builds wurden intern
als 1.0.0 ausgeliefert, unabhängig vom Release, unter dem sie veröffentlicht wurden.

**Nur macOS.** Dies ist die Version, die verwendet werden sollte. Es gibt kein
Windows-Paket: Der Windows-Quellbaum wurde auf v9 umgestellt, aber die
WPF-Anwendung kann nur unter Windows gebaut werden und wurde nie gegen v9
gebaut oder getestet. Der macOS-Build ist nicht notarisiert.

## Mit den meisten Suiten konnten keine Archive erstellt werden

Die KPAR2-Reparaturdatei prüfte ihre Suite-ID gegen einen fest codierten Bereich
von 0..1 aus der Zeit, als es nur zwei Verschlüsselungsverfahren gab. Jede
seitdem hinzugefügte Suite, einschließlich des v9-Standards und der
Paranoia-Kaskade, erzeugte einen Container, den die App verschlüsselte und dessen
Schutz sie anschließend mit *"KPAR2 has no valid encrypted KDF bootstrap parameters"*
verweigerte. Die Prüfung fragt jetzt den Katalog ab, genauso wie der Container.

Wenn du 3.0.0 heruntergeladen hast, ist dies der Grund, es zu ersetzen.

## Jede ausführbare Datei trägt jetzt beide Signaturen

Drei von Avalonia mitgebrachte Bibliotheken, `libSkiaSharp`, `libHarfBuzzSharp`
und `libAvaloniaNative`, trugen überhaupt keine Post-Quanten-Signatur. Sie werden
in den Prozess geladen, der die Archivschlüssel hält, und stützten sich allein
auf Apples Signatur. Genau von dieser einzelnen Schutzschicht soll die App
nicht abhängen.

Zwei weitere hatten ebenfalls keine solche Signatur: **der QR-Scanner**, der
die beiden geheimen Faktoren von den gedruckten Zetteln liest, und **der Verifier
selbst**, also das eine Werkzeug, das für alles andere bürgt und deshalb das
naheliegende Austauschziel ist.

Alle **17 Mach-O-Dateien** im Paket sind jetzt signiert. Die Signaturziele werden
aus dem Bundle ermittelt, statt von Hand aufgelistet zu werden, denn eine
handgeschriebene Liste deckt immer nur das ab, an dessen Aufnahme jemand gedacht hat.

## Keep Vault prüft den Scanner

Der Scanner kann nicht für sich selbst bürgen: Eine ausgetauschte App würde
einfach behaupten, alles sei in Ordnung. Keep Vault prüft ihn bei jedem Start
gegen dieselben gepinnten Schlüssel und meldet das Ergebnis im Sicherheitsprotokoll.
Ein Fehler wird deutlich gemeldet, stoppt Keep Vault aber nicht, da der Scanner
ein separates Programm ist, dessen Code Keep Vault niemals lädt.

Seine Signatur liegt neben seinem Bundle, nicht darin: Apples Versiegelung
umfasst `Contents/Resources`, sodass eine nachträglich dort abgelegte Datei die
Versiegelung brechen würde, unter der sie liegt.

## Der Verifier schließt das Inventar

Früher stellte er seine Prüfliste aus den vorhandenen Signaturen zusammen.
Wurde eine Sidecardatei gelöscht, verschwand ihr Artefakt aus der Liste, und
das Ergebnis blieb TRUSTED; eine zusätzliche unsignierte Bibliothek im Bundle
wurde überhaupt nicht untersucht. Beides sind Dinge, die ein Angreifer mit
Schreibzugriff auf ein Bundle tatsächlich tun würde.

Jede Mach-O-Datei im Baum muss jetzt signiert sein und wird anhand ihrer
magischen Kennung statt ihres Namens erkannt. Der Launcher führt dieselbe
vollständige Suche durch, bevor er den Core startet. Ein Artefakt, das weder
mit diesen Schlüsseln signiert noch beschädigt ist, antwortet mit `NOT COVERED`
und Exitcode 2, statt in TRUSTED oder BLOCKED eingeordnet werden zu müssen.

    verified_artifacts=51
    RESULT: TRUSTED - RSA-PSS/SHA-512 and ML-DSA-87 verification passed.

Richte den Verifier auf den gesamten Ordner: Das umfasst die App, den Scanner,
den Verifier und jedes Hashmanifest. Die Manifestsignaturen (`.sha3.khsig`,

Schlüsselfingerabdrücken prüfen lässt.

## Außerdem in diesem Release

- Die Signaturschlüssel selbst sind jetzt im Ruhezustand verschlüsselt, geschützt
  durch eine Schlüsselbundbestätigung für beide Hälften des hybriden Zertifikats.
  Das betrifft diejenigen, die das Projekt bauen, nicht diejenigen, die es verwenden.
- Das README ist auf Englisch und beschreibt, was tatsächlich ausgeliefert wird:
  nur macOS, die zehn Optionen mit ihren tatsächlichen Nonce- und Schlüsselgrößen
  sowie eine längere, nicht kürzere Liste der Sicherheitsgrenzen.
- Die Salt- und Nonce-Größen auf einem Ableitungspfad stammen aus dem Katalog
  statt aus einer fest codierten Länge, die zufällig bytegenau passte.

## Paket

Enthält **beide Anwendungen**: Keep Vault und den eigenständigen QR-Scanner.
Die Dateien `Keep Vault.app.launcher.*` und `QR-Scanner.app.*` müssen neben ihren
Bundles bleiben. Beide werden bei jedem Start geprüft, und keine der Anwendungen
läuft ohne sie.

## English

Container format **v9**, unchanged from 3.0.0 — archives written by that release still open. What changed is what protects them, and the bundle now reports its own version correctly: earlier builds shipped as 1.0.0 internally regardless of the release they were published under.

**macOS only.** This is the version that should be used. There is no Windows package: the Windows source tree has been moved to v9, but the WPF application can only be built on Windows and has never been built or tested against v9. The macOS build is not notarized.

## Archives could not be created with most suites

The KPAR2 recovery file validated its suite id against a hard-coded 0..1 range, written when only two ciphers existed. Every suite added since — including the v9 default and the Paranoia cascade — produced a container the app would encrypt and then refuse to protect, failing with *"KPAR2 has no valid encrypted KDF bootstrap parameters"*. The check now asks the catalogue, the same way the container does.

If you downloaded 3.0.0, this is the reason to replace it.

## Every executable now carries both signatures

Three libraries Avalonia brings along — `libSkiaSharp`, `libHarfBuzzSharp`, `libAvaloniaNative` — carried no post-quantum signature at all. They load into the process that holds the archive keys and rested on Apple's signature alone, the single layer this app is built not to depend on.

Two more were missing it: **the QR scanner**, which reads the two secret factors off the printed sheets, and **the verifier itself** — the one tool that vouches for everything else, and therefore the obvious thing to replace.

All **17 Mach-O files** in the package are signed now. The signing targets are enumerated from the bundle instead of listed by hand, because a hand-written list only ever covers what somebody remembered to add.

## Keep Vault checks the scanner

The scanner cannot vouch for itself — a replaced app would simply claim to be fine. Keep Vault verifies it against the same pinned keys at every start and reports the result in the security log. A failure is loud but does not stop Keep Vault, because the scanner is a separate program whose code Keep Vault never loads.

Its signature sits beside its bundle, not inside: Apple's seal covers `Contents/Resources`, so a file placed there afterwards would break the seal it lives under.

## The verifier closes the inventory

It used to build its worklist from the signatures that were present. Deleting a sidecar took its artifact out of the list and still answered TRUSTED; an extra unsigned library dropped into the bundle was never looked at. Both are what an attacker who can write into a bundle would actually do.

Every Mach-O in the tree must now be signed, detected by its magic number rather than its name. The launcher runs the same sweep before it starts the core. An artifact that is neither signed by these keys nor damaged answers `NOT COVERED` with exit code 2, instead of being forced into TRUSTED or BLOCKED.

## Check your download

    "./Keep Vault Release Verifier" "Keep Vault-portable-macOS"

    verified_artifacts=51
    RESULT: TRUSTED - RSA-PSS/SHA-512 and ML-DSA-87 verification passed.

Point it at the whole folder: that covers the app, the scanner, the verifier and every hash manifest. The manifest signatures (`.sha3.khsig`, `.skein.khsig`) are included, so the ZIP can be checked all the way down to the compiled key fingerprints.

## Also in this release

- The signing keys themselves are now encrypted at rest behind one Keychain confirmation covering both halves of the hybrid certificate. This affects whoever builds the project, not whoever uses it.
- The README is in English and describes what actually ships: macOS only, the ten options with their real nonce and key sizes, and a longer — not shorter — list of security boundaries.
- Salt and nonce sizing on one derivation path comes from the catalogue rather than a hard-coded length that happened to fit to the byte.

## Package

Contains **both applications**: Keep Vault and the standalone QR scanner. The files `Keep Vault.app.launcher.*` and `QR-Scanner.app.*` must stay beside their bundles — both are verified at every start and neither runs without them.
