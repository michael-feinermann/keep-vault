Historical draft. The complete language editions below describe the state at that time. The current macOS version is [5.0.2](https://github.com/michael-feinermann/keep-vault/releases/tag/v5.0.2).

## Deutsch

Containerformat **v9**. Mit v8 oder v7 erstellte Archive **können mit diesem
Release nicht geöffnet werden**. Es gibt bewusst keinen Lesepfad für ältere Formate.

**Nur macOS.** Dies ist die Version, die verwendet werden sollte. Es gibt kein
Windows-Paket: Der Windows-Quellbaum wurde auf v9 umgestellt, aber die
WPF-Anwendung kann nur unter Windows gebaut werden und wurde nie gegen v9
gebaut oder getestet. Der macOS-Build ist nicht notarisiert.

## Zehn Verschlüsselungsoptionen

Zuerst kommen die vier Kaskaden, von der Alltagsauswahl bis zur aufwendigsten
Option, danach die sechs einzelnen Verschlüsselungsverfahren in absteigender
Schlüsselgröße:

1. **Standard:** Threefish-1024 über Kalyna-512/512
2. **Schnell:** ChaCha20-Poly1305 über AES-256
3. **Gemischt:** ChaCha20-Poly1305 über Threefish-1024 und AES-256
4. **Paranoia:** ChaCha20-Poly1305 über Threefish-1024, Kalyna-512/512, SHACAL-2-512, MARS-448 und AES-256
5. Threefish-1024, Kalyna-512/512, SHACAL-2-512, MARS-448, AES-256, ChaCha20-Poly1305

Die Namen erscheinen je nach gewählter Sprache auf Deutsch oder Englisch in
Klammerschreibweise, sowohl in der App als auch auf den gedruckten Schlüsselzetteln.

## Paranoia im Detail

Sechs Verschlüsselungsverfahren aus sechs Familien, von innen nach außen:
AES-256, MARS-448, SHACAL-2-512, Kalyna-512/512, Threefish-1024,
ChaCha20-Poly1305. Die fünf inneren Schichten sind Schlüsselstromkonstruktionen;
die äußere authentifiziert zusätzlich jeden Chunk gemäß RFC 8439.

Argon2id läuft zweimal, die zweite Runde mit eigenem Salt und beide Runden mit
denselben zwei Faktoren. Aus 2 × 384 werden 568 Byte entnommen: 376 für die sechs
Schichten, 192 für die beiden MAC-Schlüssel. Dafür sind keine zusätzlichen
Entropiepools nötig: Die erste Expansion verwendet SHA3-512, die zweite SHA-512
über denselben Snapshot. Beide Salts und beide Nonces werden im Header gespeichert.

## Nonces je Chunk

Jeder Chunk erhält für **alle** Optionen eine eigene Nonce, abgeleitet aus der
Basis-Nonce und dem Chunkindex über SHA3-512. Ein durchgehender CTR-Zähler über
beliebig große Archive wiederholt sich irgendwann, und ein wiederholter
Zählerblock unter einem Schlüssel legt das XOR zweier Klartexte offen.

## Signierung: jede ausführbare Datei, beide Signaturen

Alle **17 Mach-O-Dateien** im Paket tragen die duale RSA-PSS/SHA-512- und
ML-DSA-87-Signatur. Drei davon taten das bis vor Kurzem nicht: `libSkiaSharp`,
`libHarfBuzzSharp` und `libAvaloniaNative`, die von Avalonia mitgebrachten
Bibliotheken. Sie werden in den Prozess geladen, der die Archivschlüssel hält,
und stützten sich allein auf Apples Signatur. Genau von dieser einzelnen
Schutzschicht soll die App nicht abhängen. Die Signaturziele werden jetzt aus
dem Bundle ermittelt, statt von Hand aufgelistet zu werden.

**Der QR-Scanner** liest die beiden geheimen Faktoren von den gedruckten Zetteln
und war ebenfalls allein durch Apples Signatur geschützt; ein ausgetauschter
Scanner war vom echten nicht zu unterscheiden. Er ist jetzt mit denselben
gepinnten Schlüsseln signiert, und **Keep Vault prüft ihn bei jedem Start** und
meldet das Ergebnis im Sicherheitsprotokoll. Ein Fehler wird deutlich gemeldet,
stoppt Keep Vault aber nicht, da der Scanner ein separates Programm ist, dessen
Code Keep Vault niemals lädt.

**Der Verifier selbst** trug keine Signatur, also das eine Werkzeug, das für
alles andere bürgt und deshalb das naheliegende Austauschziel ist. Auch er ist
jetzt signiert.

Die Signaturdateien des Scanners liegen **neben** seinem Bundle, nicht darin:
Apples Versiegelung umfasst `Contents/Resources`, sodass eine nachträglich dort
abgelegte Datei die Versiegelung brechen würde, unter der sie liegt. Die
Signatur des Launchers liegt aus demselben Grund außerhalb des Bundles.
Das Installationsskript installiert den Scanner nur zusammen mit seiner Signatur.

## Download prüfen

Der Verifier wird mit dem Paket ausgeliefert. Richte ihn auf den gesamten Ordner:

    "./Keep Vault Release Verifier" "Keep Vault-portable-macOS"

    verified_artifacts=51
    RESULT: TRUSTED - RSA-PSS/SHA-512 and ML-DSA-87 verification passed.

Er lehnt jede ausführbare Datei ohne Signatur im Baum ab. Eine entfernte Signatur
oder eingeschleuste Bibliothek wird deshalb erkannt statt übersprungen. Ein
Artefakt, das weder mit diesen Schlüsseln signiert noch beschädigt ist, antwortet
mit `NOT COVERED` und Exitcode 2, statt in TRUSTED oder BLOCKED eingeordnet werden
zu müssen.

Die Manifestsignaturen (`.sha3.khsig`, `.skein.khsig`) sind einbezogen, sodass sich
das ZIP bis zu den einkompilierten Schlüsselfingerabdrücken prüfen lässt.

## Außerdem in diesem Release korrigiert

Mit keiner Suite außer den ursprünglichen zwei konnten Archive erstellt werden:
Die KPAR2-Reparaturdatei prüfte ihre Suite-ID gegen einen fest codierten Bereich,
sodass der v9-Standard und die Paranoia-Kaskade einen Container erzeugten, den die
App verschlüsselte und dessen Schutz sie anschließend verweigerte. Die Prüfung
fragt jetzt den Katalog ab, genauso wie der Container.

## Paket

Enthält **beide Anwendungen**: Keep Vault und den eigenständigen QR-Scanner.
Die Dateien `Keep Vault.app.launcher.*` und `QR-Scanner.app.*` müssen neben ihren
Bundles bleiben. Beide werden bei jedem Start geprüft, und keine der Anwendungen
läuft ohne sie.

## English

Container format **v9**. Archives written with v8 or v7 **cannot be opened** with this release — there is deliberately no read path for older formats.

**macOS only.** This is the version that should be used. There is no Windows package: the Windows source tree has been moved to v9, but the WPF application can only be built on Windows and has never been built or tested against v9. The macOS build is not notarized.

## Ten encryption options

The four cascades come first, running from the everyday choice up to the most elaborate one, then the six ciphers on their own in descending key size:

1. **Standard:** Threefish-1024 over Kalyna-512/512
2. **Fast:** ChaCha20-Poly1305 over AES-256
3. **Mixed:** ChaCha20-Poly1305 over Threefish-1024 and AES-256
4. **Paranoia:** ChaCha20-Poly1305 over Threefish-1024, Kalyna-512/512, SHACAL-2-512, MARS-448 and AES-256
5. Threefish-1024, Kalyna-512/512, SHACAL-2-512, MARS-448, AES-256, ChaCha20-Poly1305

Names appear in German or English depending on the selected language, in bracket notation, both in the app and on the printed key sheets.

## Paranoia in detail

Six ciphers from six families, inner to outer: AES-256, MARS-448, SHACAL-2-512, Kalyna-512/512, Threefish-1024, ChaCha20-Poly1305. The five inner layers are keystream constructions; the outer one additionally authenticates every chunk per RFC 8439.

Argon2id runs twice, the second round with its own salt and both rounds with the same two factors. 568 bytes are taken from 2 × 384 — 376 for the six layers, 192 for the two MAC keys. No extra entropy pools are needed for this: the first expansion uses SHA3-512, the second SHA-512 over the same snapshot. Both salts and both nonces are stored in the header.

## Per-chunk nonces

Every chunk gets its own nonce for **all** options, derived from the base nonce and the chunk index through SHA3-512. A continuous CTR counter over arbitrarily large archives eventually repeats, and a repeated counter block under one key leaks the XOR of two plaintexts.

## Signing — every executable, both signatures

All **17 Mach-O files** in the package carry the dual RSA-PSS/SHA-512 and ML-DSA-87 signature. Three of them did not until recently: `libSkiaSharp`, `libHarfBuzzSharp` and `libAvaloniaNative`, the libraries Avalonia brings along. They load into the process that holds the archive keys and rested on Apple's signature alone — the single layer this app is built not to depend on. The signing targets are now enumerated from the bundle instead of listed by hand.

**The QR scanner** reads the two secret factors off the printed sheets and was likewise protected by Apple's signature alone; a replaced scanner was indistinguishable from the real one. It is now signed with the same pinned keys, and **Keep Vault verifies it at every start** and reports the result in the security log. A failure is loud but does not stop Keep Vault, because the scanner is a separate program whose code Keep Vault never loads.

**The verifier itself** carried no signature — the one tool that vouches for everything else, and therefore the obvious thing to replace. It is signed now too.

The scanner's signature files sit **beside** its bundle, not inside it: Apple's seal covers `Contents/Resources`, so a file placed there afterwards would break the seal it lives under. The launcher's signature lives outside the bundle for the same reason. The install script places the scanner only when its signature comes with it.

## Check your download

The verifier ships with the package. Point it at the whole folder:

    "./Keep Vault Release Verifier" "Keep Vault-portable-macOS"

    verified_artifacts=51
    RESULT: TRUSTED - RSA-PSS/SHA-512 and ML-DSA-87 verification passed.

It refuses any executable in the tree that has no signature, so a stripped signature or a planted library is caught rather than skipped. An artifact that is neither signed by these keys nor damaged answers `NOT COVERED` with exit code 2, instead of being forced into TRUSTED or BLOCKED.

The manifest signatures (`.sha3.khsig`, `.skein.khsig`) are included, so the ZIP can be checked all the way down to the compiled key fingerprints.

## Also fixed in this release

Archives could not be created with any suite beyond the original two: the KPAR2 recovery file validated its suite id against a hard-coded range, so the v9 default and the Paranoia cascade produced a container the app would encrypt and then refuse to protect. The check now asks the catalogue, the same way the container does.

## Package

Contains **both applications**: Keep Vault and the standalone QR scanner. The files `Keep Vault.app.launcher.*` and `QR-Scanner.app.*` must stay beside their bundles — both are verified at every start and neither runs without them.
