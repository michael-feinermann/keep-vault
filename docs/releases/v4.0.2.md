Historical release notes. The complete language editions below describe the state at that time. The current macOS version is [5.0.2](https://github.com/michael-feinermann/keep-vault/releases/tag/v5.0.2).

## Deutsch

Containerformat **v9**. Suiten mit einer Runde sind zu 4.0.0 und 4.0.1
bytekompatibel; die Paranoia-Kaskade ist es nicht. Näheres folgt unten.

**Nur macOS.** Dies ist die Version, die verwendet werden sollte. Es gibt kein
Windows-Paket: Der Windows-Quellbaum wurde auf v9 umgestellt, aber die
WPF-Anwendung kann nur unter Windows gebaut werden und wurde nie gegen v9
gebaut oder getestet. Der macOS-Build ist mit einer Apple-Development-Identität
signiert und **nicht notarisiert**.

## Die Paranoia-Kaskade leitete ihre zweite Argon2id-Runde aus nichts ab

Paranoia benötigt 568 Byte Schlüsselmaterial und führt Argon2id deshalb zweimal
über einen 128-Byte-Credential-Prehash mit zwei verschiedenen Salts aus.
Beide Runden erhielten *denselben* Puffer, und sowohl der native PHC-Adapter
als auch der verwaltete Wrapper löschen bewusst das ihnen übergebene Passwort.
Für sich genommen ist das korrekter Umgang mit sensiblen Daten.

Das Ergebnis: In 4.0.0 und 4.0.1 **lief die zweite Runde über 128 Nullbytes.**
Sie kostete dieselbe Sekunde speicherintensiver Arbeit, übernahm aber weder
Passwort- noch Faktormaterial in den Schlüssel.

4.0.2 behält einen gesperrten Master-Prehash und gibt jedem Argon2id-Aufruf eine
frische gesperrte Kopie. Diese Kopie wird anschließend gelöscht. Headeraufbau,
beide Salts, das Argon2id-Profil und alle neun anderen Suiten sind unverändert.

**Mit 4.0.0 oder 4.0.1 geschriebene Paranoia-Container können mit 4.0.2 nicht
geöffnet werden, und umgekehrt.** Der Schlüssel unterscheidet sich tatsächlich.
Es gibt bewusst keinen Rückfall auf die fehlerhafte Ableitung: Ein automatischer
Wiederholungsversuch würde den Fehler als Downgradepfad erhalten. Wenn du ein
solches Archiv hast, entpacke es vor dem Upgrade mit der Version, die es
geschrieben hat. Archive aller anderen Suiten sind nicht betroffen.

Der Regressionstest begnügt sich nicht mit einem Verschlüsselungs-/
Entschlüsselungsrundlauf. Dieser wäre auch bestanden, solange beide Seiten
gleichermaßen falsch arbeiteten. Er berechnet die zweite Runde durch eine
unabhängige Implementierung erneut und prüft, dass sich das Ergebnis von
Argon2id über ein vollständig aus Nullbytes bestehendes Passwort unterscheidet.
Genau diese Form hatte der Fehler.

## Zwei Bedienelemente waren in der englischen Oberfläche auf Deutsch

Die Option *Originaldateien nach verifiziertem Vergleich löschen* und ihre
Erklärung waren die letzten beiden noch fest in der Layoutdatei codierten
Zeichenfolgen und blieben deshalb unabhängig von der gewählten Sprache deutsch.
Beide verwenden jetzt dieselbe Nachschlagefunktion wie jedes andere
Bedienelement. Ein Test ohne sichtbares Fenster schaltet das Fenster auf
Englisch und prüft den tatsächlichen Text, statt auf die Verdrahtung zu vertrauen.

## Der Scanner wird jetzt wie alles andere gemessen

Keep Vault prüfte `QR-Scanner.app` gegen seine hybride RSA-PSS/SHA-512- und
ML-DSA-87-Signatur, aber nicht gegen das duale SHA3-512-/Skein-1024-Manifest,
an das jedes andere Artefakt im Paket gebunden ist. Der Scanner lieferte diese
Manifeste schon die ganze Zeit mit; dass eine Komponente mit weniger Hashes
als die übrigen geprüft wurde, war ein Zufall des Entstehungszeitpunkts dieses
Codes. Beide Manifeste und die Signaturen über die Manifeste selbst werden
jetzt bei jedem Start geprüft.

## Paket

Enthält **beide Anwendungen**: Keep Vault und den eigenständigen QR-Scanner,

## English

Container format **v9**. Single-round suites are byte-compatible with 4.0.0 and 4.0.1; the Paranoia cascade is not — see below.

**macOS only.** This is the version that should be used. There is no Windows package: the Windows source tree has been moved to v9, but the WPF application can only be built on Windows and has never been built or tested against v9. The macOS build is signed with an Apple Development identity and is **not notarized**.

## The Paranoia cascade derived its second Argon2id round from nothing

Paranoia needs 568 bytes of key material, so it runs Argon2id twice over one 128-byte credential prehash with two different salts. Both rounds were handed the *same* buffer — and both the native PHC adapter and the managed wrapper deliberately clear the password they are given, which is correct hygiene on its own.

The result: in 4.0.0 and 4.0.1, **round two ran over 128 zero bytes.** It cost the same second of memory-hard work, but carried no password and no factor material into the key.

4.0.2 keeps one locked master prehash and gives each Argon2id call a fresh locked copy — that copy is the one that gets cleared. Header layout, both salts, the Argon2id profile and all nine other suites are unchanged.

**Paranoia containers written by 4.0.0 or 4.0.1 cannot be opened by 4.0.2, and vice versa.** The key genuinely differs. There is deliberately no fallback to the broken derivation: an automatic retry would preserve the defect as a downgrade path. If you hold such an archive, extract it with the version that wrote it before upgrading. Archives from every other suite are unaffected.

The regression test does not settle for an encrypt/decrypt roundtrip — that would have passed while both sides were equally wrong. It recomputes round two through an independent implementation and asserts the result differs from Argon2id over an all-zero password, which is the exact shape the bug had.

## Two controls were German in the English interface

The *Delete original files after a verified comparison* option and its explanation were the last two strings still hardcoded in the layout file, so they stayed German no matter which language was selected. Both now go through the same lookup as every other control, and a headless test switches the window to English and asserts the actual text rather than trusting the wiring.

## The scanner is now measured like everything else

Keep Vault verified `QR-Scanner.app` against its hybrid RSA-PSS/SHA-512 and ML-DSA-87 signature, but not against the SHA3-512 and Skein-1024 dual manifest that every other artifact in the package is held to. The scanner shipped those manifests all along; checking one component with fewer hashes than the rest was an accident of when that code was written. Both manifests — and the signatures over the manifests themselves — are now checked at every start.

## Check your download

    "./Keep Vault Release Verifier" "Keep Vault-portable-macOS"

    verified_artifacts=51
    RESULT: TRUSTED - RSA-PSS/SHA-512 and ML-DSA-87 verification passed.

Point it at the whole folder: that covers the app, the scanner, the verifier and every hash manifest. It refuses any executable in the tree that has no signature, so a stripped signature or a planted library is caught rather than skipped.

## Package

Contains **both applications**: Keep Vault and the standalone QR scanner, now built and released as a matching version/build pair that the build refuses to mismatch. The files `Keep Vault.app.launcher.*` and `QR-Scanner.app.*` must stay beside their bundles — both are verified at every start and neither runs without them.
