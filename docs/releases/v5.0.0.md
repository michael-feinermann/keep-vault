Historical draft. The complete language editions below describe the state at that time. The current macOS version is [5.0.2](https://github.com/michael-feinermann/keep-vault/releases/tag/v5.0.2).

## Deutsch

Containerformat v12 für Windows. Dies ist das erste Windows-Paket, das den
Kalyna-v12-Adapter enthält und die vollständige Windows-Testmenge besteht.

## Inhalt dieses Entwurfs

Nur der Windows-x64-Build ist angehängt. **Das macOS-v12-Paket fehlt** und muss
auf Apple-Hardware gebaut werden, bevor dieses Release veröffentlicht werden
kann. Das macOS-Artefakt im Release 4.0.2 verwendet Containerformat v9 und darf
hier nicht verwendet werden: v12 lehnt bewusst jede frühere Version ab. Die
Kombination mit diesem Windows-Build würde deshalb zwei Anwendungen ausliefern,
die die Archive der jeweils anderen nicht öffnen können.

## Windows

- `Keep Vault-portable-win-x64.zip` mit der App, dem QR-Scanner und dem
  mitgelieferten Release-Verifier
- `Keep Vault Release Verifier-win-x64.exe` separat, damit das ZIP vor dem
  Entpacken geprüft werden kann

Jede ausführbare Datei trägt eine Authenticode-Signatur mit RFC-3161-Zeitstempel
über DigiCert sowie ein abgetrenntes Signaturpaar aus RSA-PSS/SHA-512 und
ML-DSA-87. Beide müssen erfolgreich geprüft werden. Die Signaturwurzel wird
bewusst nicht als Windows-Vertrauenswurzel installiert; die Anwendung akzeptiert
die Signatur über ihre einkompilierten SHA-256-, SHA3-512- und Skein-1024-SPKI-Pins.

Vor der Verwendung prüfen:

```
"Keep Vault Release Verifier-win-x64.exe" "Keep Vault-portable-win-x64"
```

Erwartet werden `verified_artifacts=37` und `RESULT: TRUSTED`.

## Änderungen seit 4.0.2 auf der Windows-Seite

Der Windows-Quellbaum wurde Datei für Datei, jeweils im Paar, auf den
macOS-v12-Sicherheitsablauf portiert. Die wesentlichen Änderungen:

- **Nativer Kalyna-v12-Adapter.** Der Windows-Build enthielt zuvor überhaupt
  keine `kalyna_v12.dll`, sodass keine Kaskadensuite ausgeführt werden konnte.
  Sie wird jetzt aus derselben Quelle wie der macOS-Adapter gebaut und
  exportiert die drei v12-Einstiegspunkte.
- **Die Prozesshärtung bricht bei einem Fehler ab**, wie der macOS-Launcher,
  und funktioniert erstmals: `WerSetFlags` wurde aus `wer.dll` importiert,
  die keinen solchen Namen exportiert. Deshalb wurde die Ausnahme verschluckt
  und die Maßnahme bei jedem Start als false gemeldet. Der Export liegt in
  `kernel32.dll`. Ein Fehler der Härtung beendet den Prozess jetzt mit
  EX_CONFIG (78), bevor ein Fenster oder Schlüsselmaterial geladen wird.
- **Beim Entpacken wird nur ein unveränderter Baum installiert.** Bei der
  Validierung wird ein Fingerabdruck des Staging-Baums erfasst und am letzten
  Gate erneut gemessen. Ein dazwischen veränderter Baum wird deshalb abgelehnt.
  Windows prüfte zuvor nur, ob das Staging-Verzeichnis noch dasselbe Objekt war.
- **Container werden nicht mehr mit `File.OpenRead` gelesen.** Die drei
  Aufrufstellen öffnen sie wie unter macOS: Kein Reparse Point wird verfolgt,
  und das Objekt wird als reguläre Datei nachgewiesen.
- **Die verifizierte Originallöschung** liest jede Quelle über ihren gebundenen
  Handle vor der Umbenennung in die Quarantäne erneut, nicht erst danach.
  Das Quarantäneverzeichnis wird mit einer geschützten diskretionären
  Zugriffsliste erstellt, statt die Liste des Elternverzeichnisses zu erben.

## Plattformübergreifende Formatkompatibilität

v12 berechnet Skein-MAC-1024-1024 unter macOS über den Skein-1.3-Referenzadapter
und unter Windows über `SkeinMac` von Bouncy Castle. Beide wurden gegen
veröffentlichte Vektoren geprüft; gegeneinander waren sie zuvor nie geprüft
worden. Genau dort hätte ein einziges abweichendes Bit ein macOS-Archiv unter
Windows unlesbar gemacht, während beide Testmengen weiterhin erfolgreich waren.

`crypto.skein-mac-cross-implementation` führt jetzt beide Implementierungen
mit denselben Eingaben aus: die fünf Produktionsdomänen, Skeins Blockgrenzen,
eine Nachricht von einem Mebibyte, Nicht-ASCII-Personalisierung und
256 randomisierte Runden. Das sind 288 Fälle, bei denen alle 128 Ausgabebytes
verglichen werden. Sie sind Byte für Byte identisch.

Die einzige dokumentierte Abweichung liegt außerhalb des vom Format verwendeten
Bereichs: Bouncy Castle lehnt einen Skein-Schlüssel unter 128 Bit ab, der
Referenzadapter akzeptiert Schlüssel ab einem Byte. v12 verwendet die vollen
256 Byte von A || B als Schlüssel des Credential-MACs, und kein Rollenschlüssel
ist kürzer als 64 Byte.

## Testnachweise

8 Smoke-Tests und 35 umfassende Gruppen, alle unter Windows 11 26200 bestanden,
einschließlich der KPAR2-v4-Grenzen, kryptografischer Löschung,
ZPAQ-Pfadtraversierung, des Korpus fehlerhafter Pipe-Eingaben,
ML-DSA-87-Interoperabilität und des Argon2id-Vergleichs gegen die PHC-Referenz-CLI.

Manueller Rundlauf über die Benutzeroberfläche: unverschlüsseltes Archiv und
Entpackung bytegleich; verschlüsselter Container mit
Threefish-1024-CTR(Kalyna-512/512-CTR)+HMAC-SHA3-512+Skein-MAC-1024 geschrieben,
mit allen vier Credentials entschlüsselt und bytegleich; eine falsche PIN am
Container-MAC und erneut an den zweifach authentifizierten KPAR2-Metadaten
abgelehnt, ohne zurückbleibende Teilausgabe.

## Nicht geprüft

- Diesem Entwurf liegt kein macOS-v12-Paket bei.
- Kein externes kryptografisches Audit, kein formaler Beweis, kein physischer
  Lauf mit 1 TB.

## English

Container format v12 for Windows. This is the first Windows package that
carries the Kalyna v12 adapter and passes the full Windows suite.

## What is in this draft

Only the Windows x64 build is attached. **The macOS v12 package is missing**
and has to be built on Apple hardware before this release can go out. The
macOS artifact on release 4.0.2 is container format v9 and must not be used
here: v12 refuses every earlier version by design, so pairing it with this
Windows build would ship two applications that cannot open each other's
archives.

## Windows

- `Keep Vault-portable-win-x64.zip` with the app, the QR scanner and the
  shipped release verifier
- `Keep Vault Release Verifier-win-x64.exe` separately, so the ZIP can be
  checked before it is unpacked

Every executable carries an Authenticode signature (RFC-3161 timestamped via
DigiCert) and a detached RSA-PSS/SHA-512 plus ML-DSA-87 pair. Both must verify.
The signing root is deliberately not installed as a Windows trust root; the
application accepts the signature through its compiled SHA-256, SHA3-512 and
Skein-1024 SPKI pins.

Verify before use:

```
"Keep Vault Release Verifier-win-x64.exe" "Keep Vault-portable-win-x64"
```

Expect `verified_artifacts=37` and `RESULT: TRUSTED`.

## Changes since 4.0.2 on the Windows side

The Windows tree was ported to the macOS v12 security flow file pair by file
pair. The substantive changes:

- **Kalyna v12 native adapter.** The Windows build previously had no
  `kalyna_v12.dll` at all, which meant no cascade suite could run. It is now
  built from the same source as the macOS adapter and exports the three v12
  entry points.
- **Process hardening fails closed**, the way the macOS launcher does, and it
  works for the first time: `WerSetFlags` was imported from `wer.dll`,
  which exports no such name, so the exception was swallowed and the measure
  reported false on every start. The export lives in `kernel32.dll`. A
  hardening failure now ends the process with EX_CONFIG (78) before any window
  or key material loads.
- **Extraction installs only an unchanged tree.** The staging tree is
  fingerprinted at validation and re-measured at the final gate, so a tree
  modified between the two is refused. Windows previously checked only that the
  staging directory was still the same object.
- **Container reads no longer use `File.OpenRead`.** The three call sites open
  the way macOS does: no reparse point is followed and the object is proven to
  be a regular file.
- **Verified original deletion** re-reads each source through its bound handle
  before the quarantine rename, not only after, and the quarantine directory is
  created with a protected discretionary list instead of inheriting the
  parent's.

## Cross-platform format compatibility

v12 computes Skein-MAC-1024-1024 through the Skein 1.3 reference adapter on
macOS and through Bouncy Castle's `SkeinMac` on Windows. Both were checked
against published vectors; neither had ever been checked against the other,
which is the one place a single differing bit would have made a macOS archive
unreadable on Windows while both suites stayed green.

`crypto.skein-mac-cross-implementation` now runs both implementations on the
same inputs: the five production domains, Skein's block boundaries, a one
mebibyte message, non-ASCII personalisation and 256 randomised rounds, 288
cases, all 128 output bytes compared. They are identical byte for byte.

The one documented divergence is outside the range the format uses: Bouncy
Castle refuses a Skein key shorter than 128 bits, the reference adapter accepts
one byte upwards. v12 keys the credential MAC with the full 256-byte A || B and
no role key is under 64 bytes.

## Test evidence

8 smoke tests and 35 comprehensive groups, all passing on Windows 11 26200,
including the KPAR2 v4 boundaries, cryptographic erase, ZPAQ traversal, the
malformed pipe corpus, ML-DSA-87 interoperability and the Argon2id comparison
against the PHC reference CLI.

Manual round trip through the user interface: unencrypted archive and
extraction byte identical; encrypted container with
Threefish-1024-CTR(Kalyna-512/512-CTR)+HMAC-SHA3-512+Skein-MAC-1024 written,
decrypted with all four credentials and byte identical; a wrong PIN refused at
the container MAC and again at the dual-authenticated KPAR2 metadata, with no
partial output left behind.

## Not verified

- No macOS v12 package accompanies this draft.
- No external cryptographic audit, no formal proof, no physical 1 TB run.
