# Keep Vault 5.0.3: isolated native GUI release audit

Status, 2026-10-12: implementation built in a managed development assembly; four targeted groups actually passed, including initialization close/join. These headless results do not grant installed native GUI approval. The new build-21 Universal/AOT candidate, signatures, notarization, installation and public-distribution proof remain separate until their actual execution. Existing build-20 results remain bound to build 20. The user requested a provisional GitHub release and postponed the long/performance campaign; no overall release gate is granted by this document.

## Scope and activation

The ordinary application does not activate diagnostic observers or fault hooks. The exact startup selector `--release-audit <case>` accepts only `profile`, `rng-routing`, `rng-shuffle1`, `rng-shuffle2`, `rng-xor`, `mlock-first`, `cleanup-before-unlock`, `cancel-shuffle1`, `cancel-shuffle2`, `cancel-replay-sha3`, or `cancel-replay-sha512`. Extra options, filenames, provider selectors and malformed audit switches are rejected. There is no environment, settings, plugin, IPC, external fixture or arbitrary hook configuration.

Selection occurs after `MacProcessHardening.Apply`. Fixture initialization and hook installation remain unavailable until the real main window has completed the existing app and native-tool integrity checks. The installed launcher still verifies Apple/hybrid signatures, the supervisor and rollback anchor and forwards the fixed selector to the same AOT executable. The audit must be launched through `Contents/MacOS/Keep Vault Launcher`, never by bypassing it or patching signed bytes.

Every audit process displays an explicit public-test-data warning. Preferences are held in memory, independently of normal user preferences. The private app work directory is created exclusively through a no-follow parent descriptor below Application Support. Its held inode and 0700 mode are checked; exports use exclusive descriptor-relative 0600 files. Public evidence and fixtures are retained for review without path-based recursive deletion.

The one background initializer is registered under a lifetime gate before it can race window closure. Its public fixture/record loops check the real window cancellation token. Window disposal cancels and joins this background-only worker before resetting shared entropy pools or disposing audit-owned descriptors/snapshots. It does not require a UI continuation to exit. Initialization failure/cancellation after window disposal cannot show a new dialog or populate controls.

## Public fixture and real GUI work

`profile` generates a declared exact 256-MiB public tree matching the REV12 mixed-data fixture algorithm: empty, nested, hidden and Unicode directories, an empty file, a small fixed text and a payload with approximately 75% fixed patterns and 25% fixed SplitMix64 synthetic bytes. The PRNG constructs public file contents only and is never an entropy, RNG, KDF, salt or nonce provider.

Hashes computed over the declared writes are compared with independent reads. The complete creation-snapshot topology must match the declared entries. Later creation requires the same source snapshot and manifest, encrypted output, compression level 3, unchanged fixed destination, declared public password/PIN and retained originals. Extraction/list/recovery accept only that owned archive; extraction additionally uses the normal product bitwise and topology comparison. Native launcher/startup checks, KDF costs, authentication, budget admission, key-sheet binding, capture safeguards and normal dialogs remain active.

The operator clicks the real Generate, key-sheet, Archive and Extract controls and provides real mouse entropy for the positive profile case. This code does not call those handlers to manufacture GUI evidence. Normal file pickers and dialog interactions, capture/layout/scrolling and all five AEAD workflows still need independent actual-GUI observations. A diagnostic receipt alone does not replace them.

## Passive phase measurements

The session reuses the callback-free phase, native-executor and global-MAC observers. A new callback-free CPU allocator observer records only already committed grants, reservations and acquire durations. It cannot change a grant, topology, cancellation, scheduling or operation result. Scopes flow through the real asynchronous GUI operations and are restored after actual service cleanup and joins. Diagnostic failure marks unavailable evidence and cannot confer archive success.

The bounded source-generated JSON DTO contains only version/build, actual PID/slice, executable and Info.plist SHA-256, public fixture manifest/size/counts, requested CPU settings, actual phase/grant aggregates, bounded entropy phase names/times, terminal disposition and cleanup counters. It contains no passwords, PIN values, factors, salts, PMI/matrix detail, nonces, raw mouse/RNG bytes, permutations, memory addresses, exception messages or arbitrary logger output. Actual native provider inventory and source/SDK/compiler provenance must be bound independently by the release runner to these actual binary hashes. Self-reported metadata is not an independent signature verifier.

Application dialog wait is reported separately. The handler timer starts at `BeginOperation`, which for creation follows normal preflight and source checks; it is not the entire click-to-terminal interval. Work walltime excludes measured `ShowAsync` dialogs but may include direct `ConfirmAsync`, file-picker and operator waits. Process CPU time is distinct from walltime and excludes unobserved child CPU time. Phase and native callback/queue/join intervals overlap; their sums are not additive total walltime. Source bytes, compressed payload bytes and repeatedly processed cipher bytes are different rate denominators. Entropy phase entries record internal phase entry, not phase completion or proof of an actual screen paint. Missing observations and timeline omissions must be considered by the gate checker. Repeated quiet admitted trials, medians, spread, actual Auto/1/additional grants and an honest before/after corpus comparison remain necessary.

## Fixed negative cases and ownership

Fault cases are one-use separate application processes. They do not collect real mouse records and cannot operate on normal archives, extract, erase, print, export key sheets or publish new generated factors. The explicit public canonical-record fixture passes the actual record-admission and OS-random pool-routing paths until all eleven actual pools are ready. These cases are not human-capture evidence.

Only the compiled selected fault is armed for the actual Generate operation. Every nonfailed RNG role forwards to the same reviewed OS adapter. RNG failures are controlled adapter exceptions, not a claim that Apple's CSPRNG physically failed. `mlock-first` returns ENOMEM rather than faking a successful OS lock. The cleanup case throws once after zeroing and before the genuine unlock; retained owners can retry through the real cleanup paths. It does not return fake unlock success.

Shuffle cancellation follows the beginning of the actual role-specific RNG refill; replay cancellation follows a successfully hashed public record in the chosen SHA3/SHA512 round. All accepted workers must join before observer disposal, hook removal, reset/retry and export. An unexpectedly returned result is rejected before factor publication and explicitly marked `unexpected-fault-result-blocked`; the checker must not treat that deliberate rejection as the requested fault having worked.

The receipt's `expectedControlledFaultObserved` is a narrowly defined observation, not PASS or overall approval. A gate must additionally require actual UI error/cancel behavior, nonpublication, case/PID/binary binding, no outstanding work, successful cleanup retry and the matching documented claim. A phase-start hook or timeout does not prove an in-replay cancellation. There is no crash/power-loss physical-erasure guarantee.
